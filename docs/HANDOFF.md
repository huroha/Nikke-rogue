# 작업 인수인계 노트

다른 PC에서 이어서 작업할 때 읽는 문서입니다. 지금까지 무엇을 만들었고, 각 부분이 어떻게 동작하는지, 다음에 무엇을 할지 정리했습니다.

마지막 업데이트: 2026-10-05

---

## 0. 새 PC에서 시작하기

```bash
git clone https://github.com/huroha/Nikke-rogue.git
cd Nikke-rogue
npm install
npm run dev     # http://localhost:5173 에서 플레이
npm test        # 규칙 테스트 15개
```

- 필요한 것: Node.js 22 이상, git
- 배포된 버전: https://huroha.github.io/Nikke-rogue/ (`main`에 push하면 자동 배포)
- Claude Code 플러그인 **superpowers**(작게 계획하고 단계별로 진행하는 스킬 모음)를 쓰고 있었다면 새 PC에서도 설치합니다.
  ```bash
  claude plugin marketplace add obra/superpowers-marketplace
  claude plugin install superpowers@superpowers-marketplace
  ```

### 작업 방식 메모

- 한 번에 크게 만들지 않습니다. **짧은 계획 → 한 단계 구현 → 무엇이 바뀌었는지 확인** 순서로 진행합니다.
- 몬스터는 전부 **오리지널**입니다. 포켓몬의 이름, 그림, 기술명은 쓰지 않습니다.
- 그래픽은 지금은 도형과 텍스트로 대신하고, 도트 그림은 직접 만들어서 넣을 예정입니다(6장 참고).

## 1. 전체 구조

```
Nikke-rogue/
├─ src/core/      ① 게임 규칙 (화면과 무관한 순수 로직)
├─ src/scenes/    ② 화면 (Phaser 씬)
├─ src/ui/        ③ 공용 UI 부품 (버튼, HP바, 색상)
├─ src/session.ts ④ 현재 진행 중인 런 보관 + 저장/불러오기
├─ src/main.ts    게임 시작점 (씬 등록)
├─ tests/         ⑤ 자동 테스트
└─ 설정 파일들     ⑥ 빌드·배포
```

**핵심 원칙: 규칙과 화면을 분리합니다.**
`src/core/`는 화면을 전혀 모릅니다. 전투 규칙은 상태를 바꾼 뒤 "무슨 일이 일어났는지" 목록(`BattleEvent[]`)을 돌려주고, 화면은 그 목록을 차례로 연출하기만 합니다.
그래서 그래픽이나 연출을 바꿔도 규칙이 깨지지 않고, 규칙은 브라우저 없이 테스트할 수 있습니다.

기술 스택은 TypeScript, Phaser 3(2D 게임 엔진), Vite(개발 서버와 빌드), Vitest(테스트)입니다.

## 2. 게임 규칙 `src/core/`

### 2-1. 데이터 (`data/`, `types.ts`)

게임에 등장하는 것들의 목록만 있고, 동작 코드는 없습니다.

| 파일 | 내용 |
|---|---|
| `data/species.ts` | 몬스터 14종. 이름, 속성(1~2개), 기본 능력치 6개(HP·공격·방어·특공·특방·스피드), 레벨별 습득 기술, 진화 조건, 포획 난이도(`catchRate` 0~1), 처치 경험치(`expYield`). `STARTERS`에 스타터 3종이 들어 있습니다. |
| `data/moves.ts` | 기술 26개. 속성, 물리/특수/변화 구분, 위력, 명중률(null이면 필중), PP, 선공 우선도, 부가효과. `STRUGGLE`(몸부림)은 PP가 전부 떨어졌을 때만 쓰는 숨은 기술입니다. |
| `data/typeChart.ts` | 9개 속성(무속성·화염·해류·초목·전격·암석·질풍·그림자·광휘)의 상성표. 속성이 2개인 상대에게는 배율을 곱합니다(예: 해류 → 암석/화염 = 4배). |
| `types.ts` | 위 데이터의 형식 정의. `MonsterInstance`는 런 안에서 실제로 살아 움직이는 개체(레벨, 경험치, 현재 HP, 기술과 남은 PP)입니다. |

부가효과(`MoveEffect`)는 네 가지입니다.
- `stage`: 능력치 랭크 ±(자신 또는 상대, 확률 지정 가능)
- `heal`: 최대 HP 비율만큼 회복
- `drain`: 준 데미지 비율만큼 회복
- `recoil`: 준 데미지 비율만큼 반동

몬스터나 기술을 추가할 때는 이 파일들에 항목을 하나 추가하기만 하면 됩니다.

### 2-2. 몬스터 개체 (`monster.ts`)

- `calcStats`: 레벨과 기본 능력치로 실제 능력치를 계산합니다(포켓몬과 비슷한 공식, 개체값과 노력치는 없음).
- `createMonster`: 해당 레벨까지 배울 수 있는 기술 중 **마지막 4개**를 가진 채로 생성합니다.
- `gainExp`: 경험치를 받으면서 레벨업 → 새 기술 습득 → 진화 확인을 합니다. 결과는 `ProgressStep[]`(메시지, 기술 교체 선택, 진화) 목록으로 돌려주고, 화면이 이것을 하나씩 보여줍니다.
  - 기술이 4개 미만이면 자동으로 배우고, 4개면 `learn` 단계를 만들어 플레이어가 잊을 기술을 고르게 합니다.
  - 진화는 바로 적용하지 않고 `evolve` 단계로만 남깁니다. 실제 적용은 화면에서 연출할 때 합니다.
- `evolve`, `learnMove`, `healHp`, `restorePp`: 각각 진화 적용, 기술 교체, HP 회복, PP 회복입니다.
- 레벨업이나 진화로 최대 HP가 늘면 늘어난 만큼 현재 HP도 같이 오릅니다.

### 2-3. 데미지 (`damage.ts`)

```
기본값 = ((2×레벨/5 + 2) × 위력 × 공격/방어) / 50 + 2
최종 = 기본값 × 자속(1.5) × 상성 × 급소(1.5) × 난수(0.85~1.0), 최소 1
```

- 물리 기술은 공격/방어, 특수 기술은 특공/특방을 씁니다.
- 랭크 배율은 +n이면 (2+n)/2, −n이면 2/(2+n)입니다(최대 ±6).
- 급소는 1/16 확률이고, 자신에게 불리한 랭크 변화를 무시합니다.
- 상성이 0배면 데미지도 0입니다.

### 2-4. 적 AI (`ai.ts`)

- 75% 확률로 **가장 좋아 보이는 기술**(위력 × 명중 × 상성 × 자속)을 고르고, 25%는 무작위로 고릅니다.
- 회복 기술은 자기 HP가 절반 미만일 때만 높게 평가합니다.

### 2-5. 전투 진행 (`battle.ts`)

1:1 야생 전투입니다. `new Battle(파티, 적, 난수, {capturable, isBoss})`로 만들고, `submit(행동)`을 부르면 한 턴이 진행됩니다.

**행동은 세 가지입니다.**
- `move`(기술 사용): 선공 우선도 → 스피드(랭크 반영) → 동률이면 무작위로 순서를 정하고 서로 공격합니다.
- `switch`(교체): 교체를 먼저 하고, 적이 새로 나온 몬스터를 공격합니다. 교체하면 랭크가 초기화됩니다.
- `capture`(포획): 성공하면 전투가 끝나고, 실패하면 적이 공격합니다. 보스에게는 쓸 수 없습니다.

**한 턴의 흐름(기술):** PP 차감 → 명중 판정 → 데미지 → 급소/상성 메시지 → 부가효과 → 쓰러짐 확인

**쓰러졌을 때:**
- 적이 쓰러지면 승리(`win`)입니다.
- 내 몬스터가 쓰러지고 남은 동료가 있으면 `needsSwitch = true`가 됩니다. 이때는 교체 외의 행동을 받지 않습니다.
- 전원이 쓰러지면 패배(`lose`)입니다.

**포획 확률:** `catchRate × (1 − 2/3 × 현재HP/최대HP)`이며 2%~95% 범위로 제한합니다. 상대 HP를 깎을수록 잡기 쉽습니다.

`submit`이 돌려주는 `BattleEvent` 종류는 message(문장), attack(공격 모션), hp(HP 변화), faint(쓰러짐), switch(교체), capture(포획구 흔들림 횟수), end(결과)입니다.

`participants`에는 한 번이라도 전투에 나온 동료가 기록되고, 경험치 분배에 쓰입니다.

### 2-6. 런 진행 (`run.ts`)

`RunState`는 한 판(런)의 전체 상태입니다. 현재 웨이브, 파티, 포획구 수, 난수 상태, 다음 개체 ID가 들어 있습니다.

- `createRun`: 스타터 Lv.5 한 마리와 포획구 5개로 시작합니다.
- `generateEncounter`: 웨이브에 맞는 적을 만듭니다.
  - 출현표 `WILD_POOL`: 웨이브가 지날수록 출현하는 종류가 늘어나고, 15웨이브부터는 스타터 계열도 가끔 나옵니다.
  - 레벨: `2 + 웨이브×0.6`에 −1~+1 변동을 줍니다. 단, 5웨이브 전에는 위로 튀지 않습니다.
  - 진화 레벨에 도달한 적은 진화한 모습으로 나옵니다.
  - **10웨이브마다 보스**이고, 레벨 +3에 포획할 수 없습니다.
- `finishBattle`: 승리하거나 포획하면 경험치를 나누고 웨이브를 1 올립니다. 포획한 몬스터는 파티에 들어갑니다.
  - 전투에 나온 동료는 경험치 100%, 나오지 않은 동료는 50%를 받습니다. 쓰러진 동료는 받지 않습니다.

### 2-7. 보상 (`rewards.ts`)

웨이브를 클리어할 때마다 서로 다른 보상 3개가 가중치에 따라 뽑히고, 그중 1개를 고릅니다.

| 보상 | 효과 | 등장 조건 |
|---|---|---|
| 회복의 샘 | 살아 있는 동료 HP 50% 회복 | 다친 동료가 있으면 자주 |
| 만능 회복약 | 살아 있는 동료 HP 완전 회복 | 다친 동료가 있을 때만, 드묾 |
| 불사조 깃털 | 쓰러진 동료 전원 HP 50%로 부활 | 쓰러진 동료가 있을 때만 |
| 성장 결정 | 살아 있는 동료 레벨 +1 | 항상 |
| 포획구 묶음 | 포획구 +3 | 포획구가 3개 미만이면 자주 |
| 기력 회복제 | 전원 PP 완전 회복 | 항상 |

### 2-8. 기타

- `balance.ts`: **밸런스 숫자는 전부 여기 모여 있습니다.** 스타터 레벨, 시작 포획구, 보스 주기와 레벨 보너스, 급소율, 적 레벨 증가량(0.6/웨이브), 경험치 배율(2.5), 필요 경험치(레벨³), 포획 공식.
- `rng.ts`: 시드 기반 난수입니다. 상태가 숫자 하나라 세이브에 그대로 넣을 수 있고, 같은 시드면 같은 결과가 나옵니다.
- `storage.ts`: 브라우저 localStorage에 런을 저장, 불러오기, 삭제합니다(키 `nikke-rogue:run:v1`).
- `text.ts`: 한국어 조사 처리입니다. `josa('불똥이','은','는')` → "불똥이는", `josaRo('해일뱀')` → "해일뱀으로".

## 3. 화면 `src/scenes/`

진행 순서: **Boot → Title → Starter → Battle → Progress → Reward → Progress → Battle → …**, 전멸하면 **GameOver → Title**

| 씬 | 역할 |
|---|---|
| `BootScene` | `src/assets/monsters/*.png`를 자동으로 찾아서 불러오고, 도트가 번지지 않게 최근접 필터를 겁니다. |
| `TitleScene` | 새 게임 / 이어하기(저장이 있을 때만 활성화) |
| `StarterScene` | 스타터 3종 카드(능력치, 시작 기술, 진화 정보). 클릭하면 런이 시작됩니다. |
| `BattleScene` | 전투 화면. 시작할 때 **저장**하고 적을 생성합니다. 메뉴: 싸우기(기술 4개, 속성 색 띠와 PP 표시), 교체(파티 목록), 포획. 규칙이 돌려준 이벤트를 차례로 연출합니다(메시지, 공격 모션, HP바 애니메이션, 쓰러짐, 포획구 흔들림). 메시지는 0.9초가 지나거나 클릭하면 넘어갑니다. |
| `ProgressScene` | 경험치·레벨업 메시지, 기술 교체 선택(4개 중 하나를 잊거나 배우지 않기), 진화 연출을 하나씩 처리하고 다음 씬으로 넘어갑니다. 전투 후와 보상 후 양쪽에서 재사용합니다. |
| `RewardScene` | "웨이브 N 클리어!", 보상 카드 3장, 하단에 파티 현황(레벨, HP바, 쓰러지면 흐리게) |
| `GameOverScene` | 도달한 웨이브 표시, 타이틀로 |

화면 크기는 960×540이고, 창 크기에 맞춰 비율을 유지한 채 늘어납니다.

## 4. UI 부품 `src/ui/`

- `theme.ts`: 화면 크기, 글꼴(맑은 고딕 우선), 색상, **속성별 색**, HP바 색(초록 → 노랑 → 빨강)
- `widgets.ts`
  - `Button`: 호버하면 테두리가 강조되고, 비활성이면 흐려집니다. 부제목과 왼쪽 색 띠를 넣을 수 있습니다.
  - `Bar`: HP바와 경험치바(애니메이션 지원)
  - `MonsterPanel`: 이름, 레벨, 속성 뱃지, HP바(+ 내 몬스터는 HP 숫자와 경험치바)
  - `drawMonster`: 도트 그림이 있으면 이미지를, 없으면 속성 색 사각형에 이름 첫 글자를 그립니다(듀얼 속성이면 아래에 두 번째 속성 색 띠).
  - `waitAdvance`: 시간이 지나거나 클릭/키 입력이 있으면 넘어갑니다.
  - 글자는 고해상도로 그려서 확대해도 선명합니다.

## 5. 세션 `src/session.ts`

모든 씬이 함께 쓰는 "지금 진행 중인 런"과 난수를 보관합니다.

- `startNewRun`: 현재 시각으로 시드를 만들어 새 런을 시작합니다.
- `resumeRun`: 저장된 런과 난수 상태를 복원합니다.
- `persistRun`: 웨이브 시작 시점에 저장합니다. 난수 상태까지 저장하기 때문에, 이어하기를 하면 같은 적이 다시 나옵니다(세이브 스커밍 방지).
- `endRun`: 전멸하면 저장을 지웁니다.

`main.ts`는 디버깅용으로 `window.__game`에 게임 객체를 노출합니다. 브라우저 콘솔에서 `__game.scene.getScene('battle').battle`처럼 상태를 들여다볼 수 있습니다.

## 9. 밸런스를 정한 방법

자동 플레이 봇(적 AI와 같은 방식으로 기술을 고르고, HP가 낮을 때 포획하고, 회복 보상을 우선 선택)으로 스타터별 200판씩 시뮬레이션했습니다. 시뮬레이션 코드는 커밋하지 않았습니다.

| 조정 | 이유 |
|---|---|
| 적 레벨 증가 0.9 → 0.6/웨이브, 경험치 ×2.5 | 처음에는 중앙값이 웨이브 6이었습니다(적이 너무 빨리 강해짐). |
| 보스를 강제로 최종 진화시키지 않음 | 10웨이브 보스가 벽이 되었습니다. |
| 5웨이브 전에는 적 레벨이 위로 튀지 않음 | 초반에 상성이 나쁜 적(예: 싹틔미 vs 팔랑새)에게 급소를 맞고 전멸하는 경우가 많았습니다. |

결과: 중앙값 웨이브 22~33, 2웨이브 이내 전멸 0.5~6%(봇 기준이라 사람은 더 잘할 것으로 예상).

## 10. 알려진 한계와 주의점

- **저장 시점:** 웨이브 시작 때만 저장합니다. 보상 화면에서 새로고침하면 직전 웨이브 전투부터 다시 합니다.
- **파티가 6마리면 포획 불가:** 박스나 놓아주기 기능이 없습니다.
- **기술 교체 화면과 진화 화면:** 로직은 테스트로 확인했지만, 브라우저 자동 플레이에서는 아직 화면에 뜨는 것까지 확인하지 못했습니다.
- **진화 후 기술:** 진화해도 진화형 고유의 새 기술을 따로 배우지 않습니다(현재는 진화 전후 습득표가 같음).
- **없는 것:** 상태이상, 특성, 날씨, 아이템 소지, 트레이너 전투, 메타 진행(해금, 도감), 사운드
- **이름:** 저장소와 제목의 "NIKKE"는 다른 게임의 상표입니다. 정식 이름을 정하면 바꾸는 것이 좋습니다.
